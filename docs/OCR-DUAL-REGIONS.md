# 角色能力与小地图地址双框 OCR

2026-10-25 更新。用户提供了一张拍摄游戏窗口的 JPEG；旧版本整图 Tesseract 未提取出角色名和等级。此版本在本机使用 RapidOCR / ONNX CPU 识别，不将图片提交给第三方识别 API。

## 使用

在发布招募或求车表单内粘贴、拖入或选择截图。自动定位蓝色「角色能力」框和绿色「小地图地址」框；小地图只选择文字地址，不包含下方路线图。可以拖动框、拖右下角调整大小，也可以先选区域按钮再在图片上重画。方向键微调位置，Shift + 方向键调整尺寸。改动后必须重新识别，旧结果不能直接确认。

识别后显示游戏 ID、等级、职业和地图地址；低把握字段单独提示人工核对。确认后才填入角色名、等级和挂机地图，不自动发布卡片。申请表只使用角色区域，不改变被申请队伍的地图。

- 当前测试图提取到：78 级、职业「大副」、地图「王冠之地」。角色名最后一个字不可靠，显示低把握提示，未手工写死或纠正名字。
- 地名按图中检测文字位置自动框定，没有硬编码当前截图坐标或指定地名。
- 33 项后端测试通过；最终地图框收紧后，10 项 OCR 用例再次通过。覆盖缺失等级标签、避免把血量/人气当等级、旧版英文文字、缩放布局、越界/NaN/布尔坐标拒绝、API 区域传递。
- 3 项前端几何测试通过；真实浏览器验证整图粘贴、两个自动框、拖动、重新识别、地图回填、390 像素移动布局。
- 单次完整 CLI 实图识别约 6.9 秒，进程峰值约 546 MiB；生产 OCR 仍为独立单任务服务，CPU 80%、内存上限改为 768 MiB，子进程超时 19 秒；API 22 秒超时后保留手填路径。
- 原始图片只在临时目录中处理，流程结束后删除。用户测试原图不纳入公开静态文件或源码测试样本。

## 接口

`POST /party/api/ocr/character` multipart 字段：`file`；可选 `regions` JSON。

```json
{"character":{"x":0.25,"y":0.20,"w":0.30,"h":0.65},"map":{"x":0.10,"y":0.25,"w":0.15,"h":0.10}}
```

坐标相对经过 EXIF 方向处理的图片归一化到 0..1；必须有 character，可选 map，最多两个框。省略 regions 时自动定位。回包保留 `game_id/level/text/needs_confirmation`，新增 `map_name/map_region/job/regions/confidence/uncertain_fields`。所有识别结果仅为待确认值，confidence 只是模型输出，不是准确率承诺。

依赖和模型使用：[RapidOCR 官方使用说明](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/usage/)、[参数说明](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/parameters/)。新版本安装器先预检模型，再切换服务；已有版本可按原运维说明回滚。

正式站点验证：部署版本 `20261025-ocr2`，自动备份 `/var/backups/rabbit/20261025T143005Z`。真实 HTTPS 请求返回等级 78、职业大副、地图王冠之地；仅角色名被列为低把握字段。生产 worker MemoryPeak 约 494 MiB，未出现内存或服务错误；原计时器健康接口正常。
