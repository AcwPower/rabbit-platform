# 运维与管理员说明

## 登录与后台

入口为 https://mushroom-king-timer.online/party/ 。管理员登录后进入「我的记录 → 管理后台」。初始管理员账号已创建；凭证仅保存在 `.10` 的 `/etc/rabbit/admin-initial.txt`，权限为 root 0600。源码中不含账号密码。服务器管理员可自行读取该文件，或通过下面的交互命令更换平台管理员密码：

```sh
sudo bash -c 'set -a; . /etc/rabbit/app.env; set +a; cd /opt/rabbit-platform/current/backend; /opt/rabbit-platform/current/venv/bin/python -m app.admin_cli password --username admin'
```

后台可审核评价、处理举报与角色修改申请、修改用户角色资料、查看注册截图、隐藏卡片、封禁普通账号、解除封禁、处置争议撮合并查看审计记录。管理员角色与普通玩家角色独立，管理员也可以发布自己的队伍；后台不能封禁管理员。

## 撮合规则

1. 老板可不登录申请，浏览器生成管理凭证；请保存完整管理链接。链接 `#` 后的凭证不会进入服务器访问日志，数据库只存 SHA256。
2. 队长同意后双方可见联系微信或二维码，此时仍不占坑。队长确认上车才占坑；最后一个坑位由数据库事务锁保证。
3. 结束时由打手队长单独确认，随即完成、释放坑位并开放可选评价；老板无需再确认。取消同样释放坑位并写审计；争议中的坑位保持占用，由双方或管理员处理。
4. 老板求车卡需要本人明确标记已找到，不会因同意一个接单意向自动消失。
5. 联系方式可以主动删除，到期清理；公网列表默认不公开联系方式。公开联系入口是发布者明确选择。

## 服务与路径

`.10` 上的目录：

- `/opt/rabbit-platform/releases/<版本>/`：完整源码、生产静态文件与独立 venv；`current` 指向使用版本。
- `/etc/rabbit/app.env`：数据库 URL、加密密钥和应用配置，root:rabbit 0640。
- `/etc/rabbit/ocr.env`：OCR 专用凭证，root:rabbitocr 0640。
- `/etc/rabbit/tls/`：固定后端证书及私钥；私钥仅 root 可读。
- `/var/backups/rabbit/<UTC时间>/`：数据库 gzip、配置包、版本路径、SHA256。
- `/var/log/nginx/rabbit-access.log`、`rabbit-error.log`：独立入口日志。

```sh
sudo systemctl status rabbit-api rabbit-ocr
sudo systemctl list-timers --all 'rabbit-*'
sudo journalctl -u rabbit-api -u rabbit-ocr --since '1 hour ago'
sudo /opt/rabbit-platform/current/deploy/health.sh
```

API 两个 worker，内存上限 768 MB、CPU 150%；OCR 单 worker、单任务并发，内存 768 MB、CPU 80%，本地模型子进程超时 19 秒。应用读取 OCR 超时 22 秒，故障允许手填。图片上限 5 MB、1200 万像素，解析后删除原始临时文件。浏览器保留预览直至关闭表单。

每分钟清理过期卡片、申请、会话、验证码和联系方式；每日 04:15 UTC（北京时间 12:15，最多随机延迟 5 分钟）备份；每 5 分钟健康检查，结果在 systemd journal。当前没有外部告警收件人，健康失败可由 `systemctl --failed` 与 journal 查看。

## 首次安装与网关

新服务器需安装：`nginx mysql-server python3-venv python3-dev build-essential tesseract-ocr tesseract-ocr-chi-sim tesseract-ocr-eng fonts-noto-cjk`。运行 `deploy/install-release.sh`，其 `provision.py` 仅建立本平台独立用户与数据库，不修改蘑菇王数据库。不要将此安装器用于旧计时器机器。

网关 `.238` 的原站点配置保持原路径和原 API，只增加 `/party/` location。后端公网 443 可达但限制网关来源，网关设置 `proxy_ssl_verify on`，不允许跳过证书校验。公网证书由原站点 Let's Encrypt 管理，沿用续期。后端固定证书更新后，必须同步更新网关 `/etc/nginx/rabbit-backend.crt`，并 `nginx -t` 后 reload。

首次网关修改备份在 `.238`：`/var/backups/rabbit-gateway/20261025T134003Z/mushroom-timer.conf`。`install-gateway.py` 要求提供已人工核对的原配置 SHA256；如果配置发生其他变化则拒绝覆盖。

## 备份、恢复与回滚

```sh
sudo /opt/rabbit-platform/current/deploy/backup.sh
sudo python3 /opt/rabbit-platform/current/deploy/restore-drill.py /var/backups/rabbit/<备份时间>
```

恢复演练将备份导入临时 `rabbit_restore_test`，校验表与迁移版本，再删除该临时库，不改线上库。备份与加密密钥应一起保存；仅有 SQL 而丢失 CONTACT_KEY 无法解密联系方式及注册角色截图。当前备份保存在同机；如需异地灾备，应另行配置可信存储和保留周期，不能把配置包公开上传。

相同数据库迁移版本可以代码回滚：

```sh
sudo /opt/rabbit-platform/current/deploy/rollback-code.sh /opt/rabbit-platform/releases/<目标版本>
```

脚本检查迁移版本一致后切换链接、重启本平台 API/OCR 并检查健康；失败恢复原代码。数据库版本不同会拒绝代码回滚。需恢复数据时先备份现状、明确停机窗口，再执行：

```sh
sudo /opt/rabbit-platform/current/deploy/restore.sh /var/backups/rabbit/<备份时间> --confirm-replace-rabbit-database
```

该操作覆盖 `rabbit_platform` 中备份包含的表，停止 API 和清理任务，恢复后切回备份记录的版本。不会触碰蘑菇王数据库。新增于备份之后且不在备份中的表不会自动删除，跨不兼容迁移需先审查；勿把自动生成的 `alembic downgrade` 当作生产数据恢复方案。重建机器时先在受控位置恢复配置包、对应数据库用户/授权、服务与证书，再恢复 SQL；本脚本不会盲目覆盖线上密钥。

移除路由时仅还原 `.238` 的网关配置备份并 `nginx -t && systemctl reload nginx`，原计时器进程不需要重启。
