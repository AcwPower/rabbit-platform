# 注册角色截图校验

2026-10-26：新创建的打手账号必须提交包含完整「角色能力」窗口的个人截图；历史账号登录及管理员初始化不受影响，老板匿名求车不变。

## 使用与校验范围

注册页面支持文件选择、拖入以及 Ctrl/⌘+V 粘贴。只需填写用户名、密码、验证码并上传截图；服务端识别通过后自动保存首个游戏角色，减少重复输入。注册时必须截取完整清晰的「角色能力」窗口（用户指定的左侧红框）。「个人情报」可查看其他玩家，因此不能作为注册依据；两者同时出现时也仅依据角色能力审核。

服务端检查真实图片格式、尺寸与大小，拒绝损坏文件、动图、超过 5 MB、低于 160×160 或超过 1200 万像素的图片；随后去除元数据、修正方向、最长边限制为 2000 像素，重新编码为不超过 1.5 MB 的 JPEG。OCR 和存储使用同一份净化后图片。

真实 OCR 必须识别到「角色能力」标题、名字标签及职业信息，至少两项血量/魔量/经验值/人气度标签，并至少一项力量/敏捷/智力/幸运属性。还必须识别同一面板内的角色名、职业和 1–300 的等级，最低置信度分别为 0.90、0.85、0.93。只有标题、信息截断、只有个人情报、只有宠物信息均不通过；个人情报中的字段不能补齐不合格的角色能力面板。角色名属于 OCR 结果，界面提示发布前核对。拍屏纹理导致「职业」标签漏读时，允许从同一数值列中、名字与等级之间唯一的可读文字行提取职业；仍使用原 OCR 置信度校验，不从旁边的个人情报、家族、血量或其他行猜测。姓名模糊、信息不全、无关图片不会创建账号；需重新截图。OCR 不可用时提示稍后重试，不绕过截图要求。请求验证题在识别前消耗，避免重放昂贵识别请求。

这属于图片格式与信息完整性检查，不能证明截图属于上传人、证明角色归属、排除所有图片篡改，或替代人工内容审核。不对用户展示“身份已认证”。

## 关联、存储、权限

新增 Alembic 迁移 `c29b81e3a640`，建立 `registration_proofs` 表。以 `user_id` 为主键和外键，保存加密图片、OCR 角色名/等级/职业、置信度、图片摘要及时间。账号、截图、默认角色、会话在同一数据库事务中提交，失败不留下半成品或未绑定图片。保留识别结果作为注册快照，不随角色列表编辑或删除而变化。

图片使用现有 Fernet 加密密钥加密，不写入前端静态目录，不给出公开文件地址。本人在“我的 → 游戏角色”查看；管理员在“账号管理”查看，管理员查看操作写入审计。游客返回 401，其他登录用户返回 403，封禁账号不允许读取。图片接口使用 `Cache-Control: no-store`。

原有数据库全量备份已覆盖新表，恢复必须同时保留数据库和加密密钥。无需新增文件目录或修改网关。截图随账号保留；删除申请使用现有申诉流程，删除账号时截图外键可级联清理，备份按运维保留策略管理。发布/申请表单的可选 OCR 图片仍只临时处理，不会作为注册材料保存。
